# Project Graph 关系感知布局规范 v1.5

## 1. 总原则

> 位置不必节省，优先保证可读性。

> 不是“块之间不重叠”就够了，而是块、线、标签、Section、Hyperedge 边界都必须拥有安全活动空间。

## 2. 四层空间模型

### 2.1 Content Box
节点真实矩形。

### 2.2 Visual Halo
视觉呼吸区。任何无关元素不应紧贴节点。

### 2.3 Routing Exclusion Zone
边与标签默认不得进入的外扩保护区，终止于该节点的边除外。

### 2.4 Traffic Context
根据该节点附近的关系数量、标签长度、回流边、群组边界动态追加的空间。

## 3. 动态间距

不要只使用一个统一 gap。

建议：
- 基础节点 gap：140–220 world units
- 两行关系词：再增加 60–120
- 高密度 fan-out：再增加 100–220
- 双向 / feedback：再预留单独回流通道 180–320
- Section 与 Section：最少再加 160–300 的模块安全带

图变大是允许的。

## 4. 主链 / 旁支 / 回流 / 投影

### 主链
保持方向一致、尽量直。

### 旁支
从主链侧向分出，不占主链标签区。

### 回流
优先 ArcEdge；长距离回流优先上沿、下沿或外圈空走廊。

### 投影
例如“当前状态 → 当前项目视图”，单独占 lane，不穿主链。

## 5. 标签预算
边标签必须拥有自己的空间。预算应包括：
- 字宽 / 行数
- 箭头前缓冲
- 箭尾后缓冲
- 可见线段
- 与节点 / 其他标签的间距

如果标签让线几乎不可见，布局失败。

## 6. 密集关系区
采用：
- 主干 + 扇出
- 标签稀疏化
- 不同出线侧
- 分层节点

重复“核心谓词”“主位之一”等，不必每条边都写。

## 7. Section
Section 标题下方必须有标题带。第一排节点不能顶到标题。Section 的 padding 应随内部关系复杂度增长。

## 8. Hyperedge
Hyperedge 既占边界空间，也可能占标签空间。若标签属于整个群组：
1. 先移动成员节点制造空白区，
2. 增大 padding，
3. 移动整个群组，
4. 最后才考虑改变语义表示。

## 9. 长距离回边
如果底部或顶部有连续空白走廊，应使用它。不要横穿核心节点正文区。

## 10. 大板块冲突
当不同 Section 的“活动空间”重叠：
1. 拉开大板块
2. 调整纵向层级
3. 调整路由
4. 最后才压缩内容

## 11. 二次松弛
布局至少经过：
1. 语义布局
2. 布线
3. 冲突扫描
4. 局部 / 整组松弛
5. 再验证

## 12. 失败判定
以下情况必须返工：
- 线压块
- 标签压块
- 标签互压
- Section 与 Section 活动区重叠
- Hyperedge 说明压在成员节点上
- 边色在常见深 / 浅背景上不可辨
- 箭头和标签挤掉了可见线段

# 视觉设计系统

## 目标
默认适配 Project Graph 的深色和浅色画布，尽量避免主题切换后关系线或标签消失。

## 色彩职责分离
- 节点填充：表达模块语义和层级。
- 边 / 标签：表达关系，优先可读性。

不要让边色机械继承节点填充色。

## 推荐模块语义色
可根据主题微调，但默认保留稳定映射：
- 蓝：位置 / 入口 / 归属 / 规范源
- 青绿：手势 / 交互 / 协作 / 可达性
- 紫：关系 / 输入 / 对象结构
- 赭金：生命周期 / 自动化 / 过程
- 绿：反馈 / 性能 / 校准
- 灰蓝：结构 / 工坊 / 元系统

## 边色原则
边色使用中等明度、中等饱和度、高 alpha。不要使用接近背景的暗棕、暗紫、暗绿作为关系标签色。

一个可用的默认集合：
- neutral `(165,165,165,0.96)`
- blue `(89,140,205,0.96)`
- teal `(71,172,150,0.96)`
- purple `(177,121,220,0.96)`
- amber `(196,141,84,0.96)`
- green `(92,169,130,0.96)`

## 层级
同一模块只用一个色相家族，通过以下方式体现层级：
1. 大小
2. fontWeight
3. alpha
4. borderStyle
5. 留白

## 人体工学
- 重要阅读路径尽量少折返。
- 相同类型节点对齐。
- 高频关系走稳定主链。
- 次级信息降低对比度，不与主链抢注意力。
- 长期使用图避免高饱和霓虹色和过多色相。

# Project Graph 原语选择指南

## TextNode
用于实体、概念、状态、原则、规则、决策、说明。节点标题尽量短，详细解释放 Details。

## LineEdge
用于普通有向关系。优先在主链、清晰的横向/纵向关系中使用。在线上写明确关系词，而不是只靠空间位置猜关系。

## ArcEdge
用于：
- 回流 / 反馈，
- 反向关系，
- 双向关系中的第二条边，
- 长距离回边，
- 与直线主链会冲突的关系。

主链直，回流弯，是最容易扫描的默认组合。

## Hyperedge / MultiTargetUndirectedEdge
用于真正的多元共同关系或群组边界。它不是 Section 的替代品。

典型用途：
- 三个工具共同组成闭环，
- 多设备组成连续性集合，
- 多对象属于同一高阶关系。

如果 Hyperedge 的文字说明整个群组，优先通过 padding 和成员位置让它落在空白区；不要为了排版把它伪造成独立语义节点。

## Section
用于可折叠的语义模块。Section 标题下方必须预留标题带。内部节点、边标签与 Section 边界都属于布局预算的一部分。

## SyncAssociation
只用于“同一个概念的多个视图实例”。不要用它表达普通相似或关联。

## ReferenceBlockNode
用于真正应当拆成子图的复杂模块。适合：
- 跨设备层，
- 项目子系统，
- 高复杂度细节模块，
- 可独立维护的图。

引用文件应跟随 Project Graph 所需的目录结构一起交付。

## Details
将长解释、证据、例子、边界条件、理由放进 Details，而不是强行放进画布正文。
